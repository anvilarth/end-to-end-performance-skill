Блог HF об ошибке накопления градиентов в Trainer. При включённом и выключенном накоплении loss расходились. Для токенных задач среднее по micro-batch loss не равно сумме loss, делённой на общее число непаддинговых токенов шага. Авторы заявляют исправление через loss_function и передачу числа элементов батча. Измерений нет. Это ограничение корректности для накопления градиентов как способа сэкономить память. Вывод основан только на переданных записях.

## Приём 1: Нормировать суммарный loss шага накопления на общее число непаддинговых токенов всех micro-batch, а не усреднять средние по батчам.

**Наблюдение автора:** Loss различались между прогонами с накоплением градиентов и без него.

**Результат автора:** Авторы называют это корректным расчётом. Числовой эффект исправления: unknown.

**Условия и ограничения:** Токенные задачи вроде causal LM с паддингом и переменной длиной. Неясно, касается ли это распределения по рангам data parallel: unknown.

**Наш проверочный эксперимент:** Наш эксперимент: сравнить loss и градиенты одного шага при полном батче и при N micro-batch разной длины. Дополнить проверку эквивалентности из Rba2db521f1d591ed34137ee1-3 и D055 этим условием нормировки.
